Introduction                  1.1 Purpose              This Software Requirements Specification (SRS) document defines the complete functional and non-functional requirements for the Custom Blogging Platform with Role-Based Access. It serves as the authoritative reference for developers, designers, testers, and stakeholders throughout the development lifecycle.                            1.2 Project Scope              The blogging platform is a web-based Content Management System (CMS) enabling administrators to create, manage, and publish structured blog content. Public users access content through a clean, SEO-optimized frontend. The system is designed to support monetization via Google AdSense and scale into a full multi-user blogging platform in the future. Overall System Description                  2.1 System Perspective              The blogging platform operates as a standalone web application. It consists of two primary interfaces:                     Admin Panel – A protected backend system accessible only to authenticated admins with role-based permissions.                     Public Frontend – A publicly accessible interface where visitors browse and read published blog content.                        The system does not depend on third-party CMS platforms (e.g., WordPress). It is a fully custom-built application hosted on PHP/MySQL infrastructure.                            2.2 System Architecture Overview                     Presentation Layer: Tailwind CSS responsive UI (Frontend) + Admin Panel UI                     Application Layer: PHP 8.x backend with MVC structure                     Data Layer: MySQL 8.x relational database                     Hosting: Hostinger shared hosting or VPS; domain-based frontend deployment                            2.3 User Classes                  2.3.1 Super Admin (Level 2)                     Has complete control over the system                     Manages admin accounts, categories, and all blog posts                     Accesses system-wide dashboard analytics                     Can activate/deactivate admin accounts                            2.3.2 Admin (Level 1)                     Content creator role                     Can create, edit, and delete own blog posts                     Cannot manage other admin accounts or categories (view-only)                     Has a limited dashboard showing own post statistics                            2.3.3 Public User (Guest)                     No authentication required                     Can browse the homepage, blog listings, category pages, and individual posts                     Can navigate static pages (About, Contact, Terms &amp; Conditions)                                    3. Functional Requirements                  3.1 Authentication System                     The system SHALL provide a secure login page for admin users (username/email + password).                     The system SHALL validate credentials against bcrypt-hashed passwords stored in the database.                     The system SHALL create a secure session upon successful login.                     The system SHALL redirect unauthenticated users to the login page when accessing protected routes.                     The system SHALL provide a logout mechanism that destroys the session.                     The system SHALL provide a Forgot Password flow via email-based reset link.                     The system SHALL enforce role-based routing: Super Admin and Admin see different dashboards.                            3.2 Super Admin – Admin Management                     The Super Admin SHALL be able to create new Admin accounts with: Full Name, Email, Password, Role.                     The Super Admin SHALL be able to view a paginated list of all registered admins.                     The Super Admin SHALL be able to update any admin&apos;s profile details.                     The Super Admin SHALL be able to delete any admin account (with confirmation prompt).                     The Super Admin SHALL be able to activate or deactivate admin accounts.                     A deactivated admin SHALL be blocked from logging in with an appropriate error message.                            3.3 Category Management (Super Admin)                     The system SHALL allow Super Admin to create categories with: Name, Slug (auto-generated), Description (optional).                     The system SHALL allow Super Admin to edit existing categories.                     The system SHALL allow Super Admin to delete categories (with handling for posts assigned to deleted category).                     The system SHALL allow Super Admin to view all categories in a sortable list.                     The system SHALL prevent creation of duplicate category slugs.                            3.4 Blog Post Management                  3.4.1 Super Admin                     SHALL be able to create blog posts and assign them to any Admin author.                     SHALL be able to edit any blog post regardless of author.                     SHALL be able to delete any blog post.                     SHALL be able to set post status to Published or Draft.                     SHALL be able to assign or reassign category to any post.                            3.4.2 Admin (Level 1)                     SHALL be able to create new blog posts attributed to their account.                     SHALL be able to edit only their own blog posts.                     SHALL be able to delete only their own blog posts.                     SHALL be able to save posts as Draft before publishing.                     SHALL NOT be able to see or edit other admins&apos; posts.                            3.5 Blog Post Data Fields              Every blog post record must include the following fields:                                                                   Field Name                                    Data Type                                    Required                                    Description                               post_id                             INT (PK)                             Auto                             Unique post identifier                               title                             VARCHAR(255)                             Yes                             Blog post headline                               slug                             VARCHAR(255)                             Yes                             SEO-friendly URL (unique)                               description                             LONGTEXT                             Yes                             Full blog content (HTML/Markdown)                               featured_image                             VARCHAR(500)                             No                             Path/URL to featured image                               category_id                             INT (FK)                             Yes                             Foreign key ? Frontend (Public) Requirements                  4.1 Static Pages                     Home Page – Featured posts, latest posts, category navigation, AdSense slots.                     About Page – Platform/author description.                     Terms &amp; Conditions Page – Legal content.                     Contact Page – Contact form (name, email, message) with basic validation.                            4.2 Blog Pages                     Blog Listing Page – Paginated list of all published posts with thumbnail, title, author, date, and excerpt.                     Category Page – Posts filtered by selected category with the same card layout.                     Single Post Page – Full post content, featured image, author name, category, date, SEO meta tags rendered in head.                            4.3 Authentication Pages (Frontend)                     Login Page – Admin login form.                     Forgot Password Page – Email submission form for reset link.                            4.4 UI/UX Requirements                     All pages SHALL use Tailwind CSS for styling.                     All pages SHALL be fully responsive (mobile, tablet, desktop breakpoints).                     Navigation SHALL include a top navbar with logo, page links, and a search icon (future).                     Page load time SHOULD be under 3 seconds on a standard 4G connection.                     Images SHALL be compressed and optimized before storage.                     The layout SHALL follow a clean, modern aesthetic with readable typography.                            4.5 SEO Requirements                     Each blog post SHALL have a unique, slug-based URL (e.g., /blog/my-post-title).                     Each page SHALL support configurable meta title and meta description tags.                     Content SHALL use a proper heading hierarchy (H1 for post title, H2/H3 for sections).                     Featured images SHALL include descriptive alt text.                     The site SHALL generate or support a sitemap.xml for search engine indexing.                     Canonical URLs SHALL be implemented to avoid duplicate content issues.                                    5. Security Requirements                     All passwords SHALL be hashed using bcrypt with a minimum cost factor of 12.                     All user input SHALL be validated and sanitized on the server side before processing or storage.                     All database queries SHALL use prepared statements (PDO) to prevent SQL injection.                     Sessions SHALL use secure, HttpOnly, SameSite=Strict cookies.                     Session tokens SHALL be regenerated after login to prevent session fixation.                     CSRF protection SHALL be implemented on all state-changing forms (POST, PUT, DELETE).                     File uploads (images) SHALL be validated for MIME type and file extension before saving.                     Uploaded files SHALL be stored outside the web root or renamed to prevent script execution.                     Failed login attempts SHALL be rate-limited (e.g., max 5 attempts per 10 minutes).                     Admin routes SHALL be protected by server-side authentication checks on every request.                                    9. Assumptions &amp; Constraints                  12.1 Assumptions                     The hosting environment supports PHP 8.x and MySQL 8.x.                     The project owner will supply Google AdSense publisher ID and slot IDs before launch.                     Initial admin accounts (Super Admin) will be seeded directly into the database during deployment.                     Public user registration is not in scope for v1.0.                     Email/SMTP credentials will be provided by the project owner for password reset functionality.                            12.2 Constraints                     The backend must be compatible with Hostinger shared hosting PHP limitations.                     No external CMS frameworks (WordPress, Laravel optional) — custom MVC PHP preferred.                     Frontend must not rely on paid UI component libraries.                     Image file size upload limit: 2MB per image (server-side enforced).                                    13. Acceptance Criteria              The system shall be considered ready for delivery when all of the following criteria are met:                               Super Admin can log in, create an Admin account, and that Admin can log in successfully.                     Super Admin can create a category and a blog post assigned to an Admin.                     Admin can log in, create a draft post, edit it, and publish it.                     Published post appears on the public frontend with correct title, content, author, and category.                     Super Admin can delete a post and it no longer appears on the frontend.                     Attempting to access /admin without login redirects to the login page.                     Password reset email is received and the reset link allows setting a new password.                     All pages render correctly on mobile (320px width) and desktop (1280px width).                     Page HTML includes correct meta title and meta description for a published blog post.                     SQL injection test on login form returns no unauthorized access.                                    14. Scalable – Architected to support future multi-user blogging, comments, analytics, and monetization expansion.                     SEO-Optimized – Structured to maximize search engine visibility from launch.
